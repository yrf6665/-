## 4. 风险预案

| 风险 | 发生了怎么办 |
|---|---|
| 统一身份认证对接审批或测试账号未及时到位 | 尽早联系学校信息中心；先按约定的认证接口边界开发和联调，测试账号到位后验证；上线前必须完成真实认证接入。 |
| 两周总工时约 60 小时，S 类无法全部实现 | Must 保持在 36 小时估算上限；超出时先缩减/后移 S 类，保留集成、测试和交付时间。 |
| 组员姓名、专业或投入时间与角色假设不符 | 第 5 周开始前核对人员表，按真实技能重新分配任务；不得把未确认的负责人当作已落实。 |
| 1000 人并发、5 秒响应难以在课堂环境复现 | 记录测试环境、并发工具和实际结果；如未达到验收口径，报告实测数据和瓶颈，不以低并发结果替代。 |
| AI 验收样本或历史 Excel 数据未准备好 | AI 分类和历史导入保持在后续候选；收到数据并核实字段、标签后再估算和排期。 |

## 5. 协作约定

- 每次上课开始做 5 分钟站会：昨天做了什么、今天做什么、卡在哪里。
- 所有改动通过分支和合并请求合入，不直接推送 `main`。
- 提交信息使用约定式提交：`feat:` 新功能、`fix:` 修复问题、`docs:` 文档、`test:` 测试。
- 每项代码至少由另一位组员审查；测试由非该任务实现者交叉执行。
- 第 5 周周三前发现任务可能延期时，立即通知组内并调整范围，优先保护核心报修闭环。
