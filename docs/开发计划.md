## 1. 小组角色分工

按专业分工，但**每个人都要写代码**，每人至少要负责一个完整的功能，从接口到页面都要做。

| 角色 | 负责人 | 专业 | 主要职责 | 第 5 周负责的功能 | 第 6 周负责的功能 |
|---|---|---|---|---|---|
| 组长 / 产品负责人 | | | 维护需求文档、主持站会、和"甲方"（老师）沟通 | | |
| 后端负责人 | | 计算机 | 数据库设计、接口规范、代码评审 | | |
| 前端负责人 | | | 页面与联调 | | |
| 数据负责人 | | 大数据 | 统计接口、历史数据导入、图表 | | |
| AI 功能负责人 | | 人工智能 | 报修智能分类、紧急程度判断、降级方案 | | |
| 测试负责人 | | | 根据验收标准写测试、提缺陷 | | |

> 5 个人时：组长由某个角色兼任，测试由所有人轮流交叉做。**谁写的代码，就由另一个人来审。**

## 3. 里程碑

| 时间 | 里程碑 | 验收方式 |
|---|---|---|
| 第 4 周末 | 需求定稿；仓库建好；骨架能跑 | 老师检查需求报告，`uvicorn` 能启动 |
| 第 5 周末 | 数据库 + 核心接口可用（提交、派单、处理、完成） | 用接口文档页面（/docs）现场演示 |
| 第 6 周末 | 页面联调、测试通过、本地部署演示 | 现场完整走一遍报修流程 |

## 4. 风险预案

| 风险 | 发生了怎么办 |
|---|---|
| 某个功能做不完 | 优先保住 M 类需求，S/C 类往后挪；**第 5 周周三前必须预警** |
| 有组员掉队 | 组长在站会上发现，组内结对帮扶；连续两次没完成要报告老师 |
| AI 接口不可用 | 报修分类退回到关键词规则，见需求文档的降级要求 |

## 5. 协作约定（详见《06_团队协作规范》）

- 每次上课开始做 **5 分钟站会**：昨天做了什么、今天做什么、卡在哪里
- 所有改动都通过 **分支 + 合并请求（PR）** 合入，不直接推 main 分支
- 提交信息用**约定式提交**：`feat:` 新功能 / `fix:` 修 bug / `docs:` 文档 / `test:` 测试
